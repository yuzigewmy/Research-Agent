# 专利技术交底工作流

创建「专利技术交底」项目时填写技术方案名称。启动 `patent-disclosure-v2` 时可填最多 4 KiB 的技术说明，并选择最多四份项目内的 UTF-8 文本或 Word 版本。材料编号与 SHA-256 随运行保存。写作使用说明和所选材料节选，也可从一段说明开始。

| 步骤 | 交付成果 |
| --- | --- |
| 固定技术材料 | 登记材料版本及内容摘要，列出需要补充的证据。 |
| 梳理技术方案草案 | 分列问题、组成、操作流程、实施依据和待核实项，默认等待确认。 |
| 编写技术交底稿 | 按确认的草案和原材料编写八节 Markdown 正文。 |
| 编制技术附图 | 从固定交底稿生成系统框图和操作流程图。可下载附图 JSON 与两张 SVG。 |
| 核对交底成果 | 核对规定章节，登记成稿、草案、附图与固定材料的 SHA-256，并列出提交前需要人工复核的内容。 |

八节正文依次为「技术领域」「现有技术与问题」「技术方案」「实施方式」「附图说明」「建议保护点」「可选实施方案」「技术效果与待核实项」。术语和效果以材料可支持的范围为准。无法核实的技术效果、检索结论、专利号和未提供的实施细节均列入待核实项。第二版保存两张附图、交底稿成果编号及其 SHA-256。附图步骤失败时，从该步骤继续可复用交底稿。第一版运行沿用四步流程。

可将成稿保存到工作区，配置 Word 组件后从固定版本导出可编辑 Word。运行沿用工作流的历史下载、暂停、继续和重跑，重跑上游会标记受影响的下游成果。

## 下载带附图的 Word

在 Word 导出所用的 Python 环境安装[附图导出依赖](<../internal/wordexport/requirements-figures.txt>)，设置 `RESEARCH_WORD_PYTHON` 和 `RESEARCH_PDF_FONT`。字体应覆盖附图标签所用字符。重启服务后，可在「编制技术附图」的当前成果或成果历史中点击「下载带附图的 Word」。文档在可编辑的交底正文后加入系统框图、操作流程图和两条图注。

每次导出按所选附图成果找到对应的交底稿，校验稿件 SHA-256。浏览器核对附图成果编号及 DOCX 摘要后保存。重跑交底稿后仍可从历史附图下载原版正文和附图。

Go 回归覆盖固定资料、确认、附图续跑和组件缺失。真实 Word 组件回归核对正文可编辑、图注顺序和两张 PNG。Chrome 核对当前下载、成果重跑和历史版本绑定。
