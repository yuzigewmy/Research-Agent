# 研究工作台

研究工作台通过浏览器管理科研项目。项目记录保存在本机 SQLite 数据库中，关闭页面或重启服务后可重新打开。

## 本机运行

开发需安装 Go 1.27、Node.js 22.13 至 22.x 或 24 及更新版本，以及 pnpm 10.30.3。在仓库根目录执行以下命令。

```powershell
pnpm --dir web install --frozen-lockfile
pnpm --dir web run typecheck
pnpm --dir web run build
go test ./...
go build -tags embedweb -trimpath -ldflags "-s -w" -o ./dist/research-agent.exe ./cmd/research-agent
./dist/research-agent.exe --listen 127.0.0.1:8080 --data-dir ./data
```

在浏览器打开 <http://127.0.0.1:8080>。可以把内嵌版可执行文件单独复制到另一个目录运行，界面和 PDF 查看资源会随程序提供。默认数据目录为 `data/`，数据库文件名为 `projects.sqlite3`。Word 导出另需配置组件。 [本机包实测](<docs/acceptance.md#本机包实测>)

开发构建可省略 `-tags embedweb`，默认从 `web/dist` 读取界面。两种构建都可以用 `--web-dir` 指定界面目录。开发前端时可在服务运行期间另行执行 `pnpm --dir web run dev`。

## 当前功能

- 从自由研究、研究选题、文献综述、论文写作、开题报告、实验计划、多轮审稿、课程论文、课程报告、软件著作权材料、专利技术交底、互动问卷和工程项目创建项目。选择「多轮审稿」后，可在文本工作区直接导入 64 KiB 以内的 UTF-8 Markdown 稿件。导入会打开已保存的版本，确认后才开始审稿。
- 新建项目和草稿共用模板目录。展开「模板规格」可查看当前修订、步骤、检查点、可跳过项和默认设置。已有工作流继续沿用启动时的修订。
- 研究选题可填写补充要求，并固定文献库中最近核验的最多 20 条来源。工作流生成 8 至 12 个构想和 3 至 5 个入围项。默认采用推荐项，开启选题确认后可选择入围项或确认推荐项。工作流依据所选题目生成研究方案，可分别下载各阶段成果。
- 按显示名或研究题目检索项目，切换当前与归档列表。项目管理可修改显示名、归档和恢复。归档项目仍能通过原地址打开。
- 首页可用自然语言保存建项草稿，也可直接填写项目表单。整理草稿时，模型根据已保存的研究描述和补充说明建议项目题名、模板、目标和交付物，必要时提出一个问题。可刷新后继续编辑。确认创建时校验草稿修订，同一请求只创建一个项目。
- 草稿可上传资料并保留同名文件的各个版本。点击整理时，模型按文件名取最新版，读取最近四份文本资料各自开头最多 8 KiB。创建项目时，所有已保存版本的原件和 SHA-256 同时进入项目资料库。
- 在项目详情向模型提问。对话和回复进度保存在本机，刷新或返回项目后可继续查看。展开已完成对话的「从此对话提议任务」可填写说明并提交待确认任务。确认运行后，模型收到该轮原话、答复节选及当时引用的资料节选。关闭页面后服务继续执行，重开原对话可查看进度和下载成果。
- 在「项目管理」可保存默认协作方式。新项目默认「仅问答」，发送前可为本轮调整。选择「建议任务，确认后运行」时，支持函数调用的模型可提出一张 Markdown 研究计划卡。回复成功后可在原对话核对、修改或取消。点击「确认运行」后才会入队。刷新或重启后可继续操作同一张卡。
- 选择「所有任务先确认」时，每项研究任务都要确认。从对话发起工作流后，每个步骤执行前等待确认。「整步先确认」允许用户明确要求的研究计划、稿件检查和选区修改建议直接入队，工作流区间等待确认。
- 选择「自动推进」时，用户明确请求的任务和工作流可在依赖校验后直接入队。模板检查点需要人工确认，缺少文献的综述会显示补充文献后再确认的提示。稿件修改建议由用户应用。
- 请助手围绕具体问题分析或比较稿件时，聚焦研究卡列出一至四份已保存的 Markdown 版本。即使使用自动推进，也需确认才会向模型发送每份文件开头最多 8 KiB 的节选。报告可从原对话下载，附有文件路径、版本号和 SHA-256。
- 回复过程中可点击「停止回复」。已生成的文字会随对话保存，刷新后可查看并继续提问。
- 「后台任务」显示当前任务和排队数量。「停止当前任务」保留后续队列，遇到工作流步骤时暂停本轮，可从该步继续。「停止全部任务」需二次确认，取消确认时正在运行和排队的任务，并结束涉及的工作流。已完成的成果、已保存的审稿轮次和待确认的提议仍可查看。
- 会话开始时固定同项目最多四项尚未同步的关联任务成果。模型读取每项的任务说明和正文前 1200 个字符。回复成功后记为已同步。回复失败、停止或中断时，新一轮可继续使用这些成果。对话历史保留本轮参考的成果和下载入口。
- 提议研究计划，在确认前可修改任务说明和最多四个工作区文件版本。确认和领取任务时会核对文件版本。文件已更新时，任务须重新确认。研究模型会收到已确认文件的路径、版本、摘要及各自最多 8 KiB 的正文。任务可取消，计划可下载为 Markdown。重启后可查看已完成的成果，未完成的独立任务会显示为已中断。
- 实验项目可按顺序生成研究范围、实验计划和验收清单。开启计划检查点后，工作流等到用户确认再继续。新版实验运行可填写理由跳过末步验收清单，随后可单独补跑。重启保留检查点、跳过记录和已完成的 Markdown。排队的步骤可自动接续，执行中断的步骤可手动继续。
- 在「建议任务，确认后运行」模式下，可请助手检查一份已保存的 Markdown 稿件。模型收到最近最多 20 份稿件的路径、版本和摘要。检查卡列出所选版本，稿件更新后须换版并重新确认。确认后，本机对整份固定稿件检查章节和待补标记，报告带行号、版本和摘要，可在原对话下载。
- 在「建议任务，确认后运行」模式下，可请助手提出工作流执行区间。建议列出从当前可运行步骤到所选终点的范围。确认后按该范围启动或继续工作流，并带入原对话和引用资料节选。新运行使用模板默认设置并启用检查点。已有运行沿用原设置。若运行修订已变化，需重新提出建议。
- 启动工作流前可选择本次终点。区间完成后，从下一未完成步骤继续，可只运行该步，也可运行至后续指定步骤。每段沿用本轮设置、固定来源和已保存成果。到达区间内的检查点或遇到失败时，继续操作沿用原区间。
- 工作流排队或运行时可暂停。暂停会停止当前步骤并保留已完成成果。继续时从未完成的步骤重新执行，沿用本轮范围和输入。确认取消则结束本轮，保留已完成成果，之后可开始新一轮。重启服务后仍保留暂停与取消状态。
- 工作流停下后，可重跑已完成或待重算的单个步骤。前序成果须有效。该步和下游的旧成果可从成果历史下载，下游继续执行时使用最新的前序成果。重跑生成的稿件可另存到工作区，旧稿和人工编辑仍可查看。
- 在「运行历史」可查看以前各轮的状态、步骤和成果。开启新一轮后，仍可下载旧轮次的已完成成果及其历史版本。
- 区间完成、暂停、失败或中断后，可为支持人工验收的当前步骤选取已保存的 Markdown。改稿应用回执提供「预览此版本用于验收」，可直接选中该修订。预览并明确确认后，按文件版本和 SHA-256 登记原文为成果。论文和综述沿用本轮文献键校验。文献来源清单和稿件结构检查由系统生成。
- 项目资料可依次上传多个文件，按名称和 SHA-256 区分同名版本。每份文件上限为 64 MiB。可下载原件并预览 UTF-8 文本和 DOCX、DOTX 正文及表格的前 64 KiB 文字。Word 节选只读取正文 XML，解压上限为 16 MiB，页码、样式和图片需查看原件。备份时保留数据目录中的数据库和资料对象。
- 在项目资料中可打开 PDF 分页预览，支持跳页、缩放和选择文字。预览和下载读取同一份原件。查看器及解码资源随本机应用提供，在打开 PDF 时加载。扫描件可阅读画面，文字选择需要 PDF 自带文字。需要密码的 PDF 可下载后解锁。页面渲染和文字层使用 [PDF.js](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html#getDocument)。
- 在文本工作区选中已保存 Markdown 稿件中的文字，点击「引用稿件选区」。每轮最多引用四份不同稿件，每份选区最多 8 KiB。同一稿件再次引用会替换该稿件的选区。发送前可展开核对或逐份移除。服务端按源版本和字节范围读取选文，对话历史按选取顺序保留路径、版本、SHA-256 和选文。
- 每轮对话可引用最多四份文本、Word 或 PDF 资料。在 PDF 预览中选中一页内的文字，再点击「引用所选文字」。每份节选最多 8 KiB。PDF 文字和页码来自浏览器，服务端核对资料所属项目和 SHA-256。对话历史保留选文、页码和原件入口，从该轮发起的任务沿用相同的引用。
- 「工程项目」可从文本工作区选择已保存的单文件 HTML 启动浏览器预览。预览绑定文件版本，支持切换、恢复与停止。 [工程预览操作](<docs/engineering-preview.md>)
- 文本工作区支持从空白或八种研究文件模板创建 Markdown。可预览模板初稿、自定文件路径并从版本历史恢复旧稿。保存 `research/brief.md` 后，点击「引用研究简报」可将 8 KiB 以内的已保存全文加入下一条消息。每轮引用保留简报正文、版本和 SHA-256。 [研究文件模板](<web/src/researchDocuments.ts>)
- 文本工作区支持创建和编辑项目文件，例如 `paper/main.md`。单文件支持 512 KiB 的 UTF-8 正文。并发保存冲突时，编辑器保留本页草稿。恢复旧稿会把选中的内容保存为新版本。
- 展开项目详情的「图表工作区」可新建和打开流程图。可拖动或填写坐标来移动节点，修改标签、添加或删除连线、缩放和撤销。保存后可下载当前或历史版本的 SVG 和 1920×1280 PNG。浏览器核对源版本摘要后生成 PNG。遇到保存冲突时可另存草稿。恢复旧版会生成一个新版本。
- 启用 Word 组件后，可从当前稿件或指定历史版本生成 DOCX。标题、段落、基本强调、列表、代码和表格可以在 Word 中编辑。每个稿件版本保存自己的导出结果，可重复下载。
- 「互动问卷」项目支持编辑单选题和文本题、发布固定版本、在独立页面填写及关闭回收。可下载答卷 CSV 或保存到项目资料后分析。填写链接适用于能访问同一台本机服务的浏览器。 [互动问卷操作](<docs/questionnaire.md>)
- 在问卷分析中选择项目内不超过 8 MiB 的 UTF-8 CSV 或 XLSX。分析 XLSX 时需选择工作表。设置必答列和查重列后可逐条复核，并计算交叉统计与量表信度。报告保存原资料版本、所选工作表及判定原因，可下载为 JSON。带 `__synthetic__` 列的资料会标记为演示数据。 [问卷分析操作](<docs/questionnaire.md#分析工作簿>)
- 文献综述项目支持在 [Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) 检索文献，按 DOI 核对登记元数据并保存至项目文献库，可导出 BibTeX。检索词和待核对的 DOI 会发送给 Crossref，记录只代表元数据核对。
- 文献综述工作流从已核验库固定本轮来源，生成来源清单、主题规划和综述稿件。纳入上限默认为 20 条，可设为 10 至 80 条。可在主题规划后暂停确认。后续步骤使用同一份来源摘要，引用只能使用该清单的键。每步成果均可下载为 Markdown。完成的综述可保存到文本工作区，继续编辑并导出 Word。每轮稿件有独立路径，重复保存保留后续编辑。
- 论文写作项目可选择中文或英文，可粘贴已有大纲。工作流固定本轮设置和已核验文献，依次生成大纲、正文和带行号的结构检查，支持在大纲完成后暂停确认。检查报告包含所查稿件的内容摘要。稿件可保存到文本工作区编辑并导出 Word。
- 课程论文默认目标为 8000 字，可选择研究方法。课程报告默认目标为 10000 字，可选择报告类型，并先梳理材料与事实。两种模板均使用中文，可选择学科方向和最多四份文本或 Word 资料版本。启动时固定资料及文献，规划后可暂停确认。各节分别保存，汇编稿可进入文本工作区导出 Word。交付核对记录正文的字数范围、待补项和稿件指纹。
- 开题报告默认按硕士学术学位设置 5000 字和 30 条文献目标。本科为 3000 字和 15 条，博士为 15000 字和 50 条。可按学校要求调整目标和日期。工作流固定本轮文献和开题设置，可在规划后确认再继续。新版运行逐节生成并保存六节正文，失败后可从该节续跑。汇编稿按正文引用追加本轮参考文献。技术路线用文字或表格表达。交付核对按稿件和答辩材料的内容摘要记录栏目、字数、文献覆盖和答辩问题数量。汇编稿可保存到工作区并按版本导出 Word。旧版运行可按原步骤续跑。
- 「软件著作权材料」以软件全称建项，版本号默认 V1.0。运行时固定所选文档和源码版本，默认在操作手册草稿生成后等待确认。可上传目录、ZIP 或 TAR.GZ，将源码和说明按相对路径登记。第二版在未选用源码时依据软件说明和已保存手册生成待核对的 Python 示例。可保存手册到工作区，下载保留原源码字节的程序材料及申请信息核对单。设置 `RESEARCH_PDF_FONT` 后，可下载当前和历史程序、手册成果的分页 PDF。已完成的运行可下载含来源清单的登记材料 ZIP，并按配置纳入 PDF 和 Word。 [软件登记与字体配置](<docs/software-registration.md>)
- 「专利技术交底」固定本轮技术说明与文本或 Word 资料。默认在方案草案完成后等待确认，再编写交底稿，从固定稿件生成系统框图和操作流程图。附图可按成果版本下载为 SVG。启用附图导出组件后，可下载含对应交底稿和两张附图的 Word。交底稿也可保存到工作区继续编辑。 [专利技术交底流程](<docs/patent-disclosure.md>)
- 在编辑器和历史版本中，可将 64 KiB 以内的 Markdown 稿件提交模拟评审。报告按稿件版本与投稿目标保存，包括评分、判断、核对过的原文摘录和行号。可下载报告，失败或中断时可重试。提交和重试时，指定版本的正文和投稿目标会发送给已配置的模型。
- 「多轮审稿」按指定的 Markdown 稿件版本开始，默认最多 4 轮、目标 6 分（满分 10 分）。只在审稿副本中修订有明确意见的行。达到目标、用完轮次或没有进展时结束。每轮保存评分、意见和该轮稿件，失败后可从已保存的进度重试。
- 在已保存的 Markdown 中选择最多 8 KiB 的文字，填写修改要求后生成建议。模型收到选区、相邻节选和修改要求。确认应用后只替换原选区并保存新版本。如果稿件已更新，界面保留建议并提示重新加载。
- 也可将一至四份稿件的选区加入对话，在「建议任务，确认后运行」模式下请助手改写。局部改稿卡固定每份稿件的来源版本和字节范围，允许修改说明。点「确认运行」后生成建议。逐份核对原文、替换稿和理由，再点「应用到稿件」各自保存。换版冲突只涉及当前稿件，可从最新版本重新选区。历史卡片保留建议和每份稿件的保存回执。
- 从评审报告选择一条编号意见，可据原文摘录生成定向修订。确认应用前可核对原文、替换稿和理由。稿件改版后，定向修订需要在当前稿件中唯一定位原文所在行。旧版报告可配合手工选区改稿。
- 应用定向修订后，工作区会自动排队复查该条意见。模型收到该意见和应用版本的局部摘录。复查结果可在原意见中查看，带稿件摘要和可核对的行号。失败或中断后可重试。

## 启用 Word 导出

在专用 Python 环境安装 [Word 导出依赖](internal/wordexport/requirements.txt)，并把 `RESEARCH_WORD_PYTHON` 设为该环境的 Python 可执行文件绝对路径。重启服务即可在 Markdown 文件的编辑器和版本历史中导出。组件支持基础 Markdown，链接、图片和 HTML 作为文本保留。

```powershell
python -m venv .local/word
.\.local\word\Scripts\python.exe -m pip install -r internal/wordexport/requirements.txt
$env:RESEARCH_WORD_PYTHON = (Resolve-Path .local/word/Scripts/python.exe).Path
```

## 配置模型连接

工作台只连接用户自行配置的模型服务，不提供平台计费、充值、余额或账单。启动前设置 `RESEARCH_MODEL_BASE_URL` 和 `RESEARCH_MODEL_NAME`。模型服务需要支持 Chat Completions 流式接口。按服务要求在运行环境设置 `RESEARCH_MODEL_API_KEY`。基地址填写服务前缀，例如 `https://api.deepseek.com`，应用会附加 `/chat/completions`。项目和已有会话可离线浏览。一个数据目录运行一个服务实例。

展开首页「模型连接」可查看当前模型和推理档位。点击「测试连接」才会向已配置服务发送一条固定消息，最多等待 30 秒。测试不发送项目资料，不写入对话历史，也不向浏览器返回服务地址或凭据。修改部署配置后请重启服务。对话历史会显示每轮发送时的模型名称与推理档位。

使用 GPT-6.2 Sol 的最高推理档位时，将 `RESEARCH_MODEL_NAME` 设为 `gpt-6.2-sol`，将 `RESEARCH_MODEL_REASONING_EFFORT` 设为 `max`。默认对话的 8192 token 上限包含推理和正文。

设置 `RESEARCH_CONVERSATION_MODEL_NAME` 和可选的 `RESEARCH_CONVERSATION_MODEL_REASONING_EFFORT`，可在同一服务上添加对话备选模型。服务重启后，在项目对话的「对话模型」中切换。浏览器标签页会按项目保留选择，已发送的消息按原回执显示模型和推理档。

在同一个模型服务上提供工作流备选模型时，设置 `RESEARCH_WORKFLOW_MODEL_NAME`，并按需设置 `RESEARCH_WORKFLOW_MODEL_REASONING_EFFORT`。重启服务后，可在启动工作流前选择本轮模型，并在「步骤模型」中为指定步骤单独选模。其余步骤沿用本轮模型。续跑和重跑使用启动时保存的配置。部署端可轮换凭据。若服务地址已改动，恢复启动本轮时的地址后即可继续。

设置 `RESEARCH_REVIEW_MODEL_NAME` 和可选的 `RESEARCH_REVIEW_MODEL_REASONING_EFFORT` 后，新建的模拟评审和多轮审稿使用同一服务上的专用模型。评审详情显示提交时的模型及推理档。重试继续使用这份配置。未设置审稿模型时，新评审使用默认模型。

设置 `RESEARCH_EDIT_MODEL_NAME` 和可选的 `RESEARCH_EDIT_MODEL_REASONING_EFFORT` 后，编辑器选区、对话改稿任务及评审意见的定向修订使用同一服务上的专用模型。任务入队时保存模型与推理档，刷新后可在建议详情中查看。
